# 테트리스 단일 파일 구현 설계 (BF-1910)

## 0. 범위 및 제약 (frozen)

- **산출 파일**: `games/tetris.html` **단 하나**만 생성한다. CSS/JS를 별도 파일로 분리하지 않는다 (인라인 `<style>`/`<script>`).
- 이 문서(`docs/plans/BF-1891/implementation-plan.md`) 및 `games/tetris.html` 외의 파일을 새로 만들지 않는다.
- 파일 소유자: `games/tetris.html -> developer`. 본 문서는 developer가 따를 실행 설계이며, 여기 기술된 DOM ID/class/상태/토큰/접근성/반응형 값은 **frozen** — developer는 selector와 토큰명을 변경·재정의하지 않는다.
- `games/tetris.html`은 additive (신규 생성) 산출물이다.
- 초기화·실패(게임오버) 뒤에는 상태와 진행 표시(점수 등)가 초기값으로 돌아가고, 주 실행 control(재시작 버튼)을 다시 사용할 수 있어야 한다.

## 1. UI 계약 (frozen — 그대로 렌더링)

### 1.1 DOM 구조 / ID

| ID | 역할 |
|---|---|
| `#tetris-board` | 테트리스 보드 컨테이너 (행/셀을 담는 grid) |
| `#tetris-score` | 현재 점수 표시 영역 |
| `#tetris-status` | 상태 텍스트 표시 영역 (`role="status"`, `aria-live="polite"`) |
| `#tetris-restart` | 재시작 버튼 (`aria-label="게임 재시작"`) |

### 1.2 CSS 클래스

| 클래스 | 역할 |
|---|---|
| `.tetris-board` | 보드 컨테이너 스타일 (grid 레이아웃, 배경) |
| `.tetris-row` | 보드의 한 행 |
| `.tetris-cell` | 보드의 한 셀 (기본 빈 칸) |
| `.tetris-cell--filled` | 블록이 채워진 셀 (modifier) |

### 1.3 디자인 토큰 (CSS 커스텀 프로퍼티, `:root`에 정의)

```css
--tetris-board-bg: #111827;
--tetris-cell-border: #1f2937;
--tetris-cell-filled: #38bdf8;
--tetris-text-color: #f8fafc;
--tetris-restart-bg: #2563eb;
```

- `.tetris-board` 배경 = `var(--tetris-board-bg)`
- `.tetris-cell` 테두리 = `var(--tetris-cell-border)`
- `.tetris-cell--filled` 배경 = `var(--tetris-cell-filled)`
- 본문/상태/점수 텍스트 색상 = `var(--tetris-text-color)`
- `#tetris-restart` 배경 = `var(--tetris-restart-bg)`

### 1.4 상태 모델

세 가지 상태만 존재하며, 상태 전이는 아래 §3 흐름을 따른다.

- `ready` — 페이지 최초 로드 직후. 보드는 비어 있고 점수는 0, 안내 텍스트("시작하려면 방향키를 누르세요" 등) 표시.
- `playing` — 블록이 낙하 중. 조작 가능.
- `gameover` — 더 이상 블록을 배치할 수 없을 때. 조작(이동/회전) 비활성, 재시작만 가능.

`#tetris-status`의 텍스트 콘텐츠가 상태명을 사람이 읽을 수 있는 한국어 문구로 노출해야 한다 (예: `준비`, `진행 중`, `게임 오버`). 색상만으로 상태를 구분하지 않는다 — 상태 변경 시 반드시 `#tetris-status`의 텍스트를 갱신한다.

### 1.5 접근성

- `#tetris-restart` 버튼은 `aria-label="게임 재시작"`을 가진다.
- `#tetris-status`는 `role="status"`와 `aria-live="polite"`를 가지며, `gameover` 진입 시 텍스트 갱신으로 스크린리더에 상태 변경을 전달한다.
- 모든 상태(`ready`/`playing`/`gameover`)는 색상만으로 구분하지 않고, `#tetris-status`의 텍스트(및 필요 시 버튼의 접근성 이름)로 상태명을 노출한다.
- 키보드만으로 전체 조작(이동/회전/재시작)이 가능해야 한다 (마우스 전용 조작 금지).

### 1.6 반응형

- 320px 폭 뷰포트에서도 `.tetris-board`와 조작 UI(점수, 상태, 재시작 버튼)가 잘리거나 가로 스크롤 없이 표시되어야 한다.
- 보드 셀 크기는 고정 px이 아니라 뷰포트 폭에 비례하도록(예: `vmin` 단위 또는 컨테이너 폭 기준 `%`/`clamp()`) 구성하여 320px에서도 보드 전체가 뷰포트 안에 들어오게 한다.
- 레이아웃은 세로 방향(모바일 우선)을 기본으로 하고, 보드 위/아래에 점수·상태·재시작 버튼을 배치한다.

## 2. 게임 데이터 모델 (구현 세부, 단일 `<script>` 안)

- **보드**: 10열 × 20행 2차원 배열(`board[row][col]`), 값은 `0`(빈 칸) 또는 채워진 셀의 색상/타입 식별자. `#tetris-board`는 이 배열을 기반으로 `.tetris-row` × `.tetris-cell` DOM을 렌더링하며, 채워진 셀에 `.tetris-cell--filled`를 부여한다.
- **테트로미노**: I/O/T/S/Z/J/L 7종의 회전 상태(shape matrix)를 상수로 정의. 현재 조각(`current`)은 `{type, rotationIndex, row, col}`로 표현.
- **점수**: 정수 카운터. `#tetris-score`의 텍스트 콘텐츠로 렌더링.
- **낙하 타이머**: `setInterval` 또는 `requestAnimationFrame` 기반 tick으로 일정 간격마다 조각을 한 칸 아래로 이동.

## 3. 게임 로직 흐름

### 3.1 초기화 (`ready` 상태 진입)

1. 페이지 로드 시 보드 배열을 전부 `0`으로 초기화.
2. 점수 `0`으로 초기화, `#tetris-score` 갱신.
3. `#tetris-status` 텍스트를 `준비`로 설정.
4. 새 테트로미노를 무작위 생성해 보드 상단 중앙에 배치(아직 렌더링만, 낙하 타이머는 시작 전이거나 즉시 시작 — 구현 선택, 단 최초 방향키 입력 또는 로드 즉시 `playing`으로 전이).
5. 재시작 버튼(`#tetris-restart`)은 항상 활성 상태로 존재.

### 3.2 이동

- 좌/우 방향키: 현재 조각을 좌/우로 한 칸 이동. 이동 후 위치가 보드 경계를 벗어나거나 다른 채워진 셀과 겹치면 이동을 취소(원위치).
- 아래 방향키(소프트 드롭): 조각을 한 칸 아래로 이동. 충돌 시 §3.4(고정 처리)로 진행.
- `playing` 상태에서만 입력을 처리한다. `ready`에서는 첫 입력이 `playing` 전이를 트리거할 수 있다. `gameover`에서는 이동/회전 입력을 무시한다.

### 3.3 회전

- 위 방향키(또는 지정 키): 현재 조각의 `rotationIndex`를 다음 회전 상태로 변경.
- 회전 결과가 보드 경계를 벗어나거나 다른 채워진 셀과 겹치면 회전을 취소(원 상태 유지). (wall-kick 등 고급 보정은 범위 밖 — 단순 충돌 시 취소만 구현하면 충분)

### 3.4 낙하 및 고정 처리

1. 낙하 타이머 tick마다 조각을 한 칸 아래로 이동 시도.
2. 이동 가능하면 위치 갱신 후 재렌더링.
3. 이동 불가(바닥 또는 다른 블록에 충돌)하면 현재 조각을 보드 배열에 고정(각 셀을 채워진 값으로 기록) → §3.5(줄 삭제 판정) 실행 → 새 조각 생성 시도.
4. 새 조각 생성 위치가 이미 채워져 있으면(스폰 불가) §3.6(게임 오버)로 전이.

### 3.5 줄 삭제

1. 고정 직후, 보드의 각 행을 검사해 모든 칸이 채워진 행(full row)을 찾는다.
2. full row가 있으면 해당 행(들)을 제거하고, 위쪽 행들을 한 칸씩 아래로 이동시키며 최상단에 빈 행을 채운다.
3. 삭제된 줄 수에 따라 점수를 가산한다(예: 1줄=100, 2줄=300, 3줄=500, 4줄=800 — 정확한 배점은 developer 재량, 단 "줄 수가 많을수록 더 높은 점수"만 보장하면 됨).
4. `#tetris-score` 텍스트를 갱신한다.

### 3.6 게임 오버

1. 새 조각을 스폰할 자리가 이미 채워져 있으면 게임 오버로 전이.
2. 낙하 타이머를 정지하고, 키보드 이동/회전 입력 처리를 중단한다.
3. `#tetris-status` 텍스트를 `게임 오버`로 갱신 (`aria-live="polite"`에 의해 스크린리더가 통지받음).
4. `#tetris-restart` 버튼은 계속 사용 가능해야 한다.

### 3.7 재시작

1. `#tetris-restart` 클릭(또는 키보드 포커스 후 Enter/Space) 시, 상태와 무관하게(즉 `ready`/`playing`/`gameover` 어느 상태에서든) §3.1 초기화를 다시 수행한다.
2. 재시작 후 보드/점수/상태 텍스트가 모두 초기값으로 돌아가고, 다시 조작이 가능해야 한다 — 즉 실패(게임오버) 뒤에도 주 실행 control(`#tetris-restart`)로 항상 복구 가능해야 한다는 frozen 불변조건을 만족한다.

## 4. Edge case / 실패 케이스

- **보드 최상단에서 즉시 충돌**: 신규 조각 스폰 위치가 이미 채워짐 → 즉시 `gameover` 전이 (§3.6).
- **회전 시 경계 초과**: 벽 근처에서 회전 시 보드를 벗어나는 경우 회전을 취소하고 원래 회전 상태 유지 (단순 취소만 구현, wall-kick 미구현은 허용).
- **연속 빠른 키 입력**: 동일 tick 내 중복 입력으로 인한 이중 이동/회전이 발생하지 않도록 입력마다 1회의 board 상태 갱신만 적용한다.
- **게임 오버 상태에서의 입력**: 이동/회전 키 입력은 무시하고, 재시작 버튼만 반응한다.
- **여러 줄 동시 삭제**: 한 번의 고정으로 2~4줄이 동시에 full row가 될 수 있으므로, 삭제 판정은 고정된 조각이 걸친 모든 행을 대상으로 한 번에 검사·삭제해야 한다(행 인덱스 밀림으로 인한 판정 누락 방지).
- **재시작 반복 호출**: 재시작 버튼을 연타해도 매번 동일하게 초기 상태로 재설정되어야 하며(멱등), 이전 타이머가 중복 실행되어 낙하 속도가 빨라지지 않도록 재시작 시 기존 낙하 타이머를 반드시 정지 후 재생성한다.
- **320px 폭 뷰포트**: 보드 셀 크기를 고정 px로 하드코딩하지 않고 뷰포트 비례 단위를 사용해 가로 스크롤 없이 전체 UI(보드+점수+상태+재시작 버튼)가 보이도록 한다.

## 5. developer에게 전달하는 실행 체크리스트

1. `games/tetris.html` 한 파일에 HTML/CSS(`<style>`)/JS(`<script>`)를 모두 인라인으로 작성한다. 다른 파일을 생성하지 않는다.
2. §1의 ID/class/토큰/접근성/반응형 값을 정확히 그대로 사용한다(재정의·변경 금지).
3. §2~§4의 로직/edge case를 구현한다.
4. 최종 산출물이 `ready → playing → gameover → (재시작) → ready`로 순환 가능한지 수동으로 확인한다.
