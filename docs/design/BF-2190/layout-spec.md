# 다이제스트 마크다운 레이아웃 시안 (BF-2191)

## 1. 시안 개요

- **대상**: `release-notes-digest` 모듈이 `buildDigest`로 생성하는 마크다운 릴리즈 노트(다이제스트) 문서의 레이아웃.
- **목적**: developer(BF-2192)가 `buildDigest` 구현 시 참고할 문서 구조·헤더 레벨·항목 서식을 예시로 확정한다.
- **범위 고정**: type→섹션 매핑 표, 정렬 규칙(3~4장), 엣지 케이스 분류(5장)는 planner 실행 설계(`docs/plans/BF-2190/implementation-plan.md`)를 그대로 따르며 이 문서에서 재정의하지 않는다. 본 문서는 그 규칙을 **마크다운 레이아웃 관점(헤더 레벨·줄바꿈·bullet 서식)**에서만 구체화한다.

## 2. 문서 구조 (헤더 레벨)

| 레벨 | 용도 | 개수 | 예시 |
|---|---|---|---|
| H1 (`#`) | 다이제스트 제목 | 문서당 정확히 1개, 최상단 | `# 릴리즈 노트` |
| H2 (`##`) | 섹션 제목 (type 그룹 9종 + 분류 보류 1종) | 0~10개, 커밋 0개인 섹션은 생략 | `## ✨ 새로운 기능` |
| (헤더 없음) | 항목 — 섹션 내부 리스트 1줄 | 섹션당 0개 이상 | `- **[bf-2186]** renderBadge + HTTP 핸들러 TDD 구현` |

- H1과 첫 섹션 사이, 섹션과 섹션 사이는 빈 줄 1줄로 구분한다.
- H3 이하 레벨은 사용하지 않는다 (섹션 내부에 하위 헤더 없음).

## 3. 섹션 순서 (plan 3장 표 인용 — 재정의 아님)

| 순서 | type | 섹션 제목(H2) |
|---|---|---|
| 1 | `feat` | `## ✨ 새로운 기능` |
| 2 | `fix` | `## 🐛 버그 수정` |
| 3 | `docs` | `## 📝 문서` |
| 4 | `refactor` | `## ♻️ 리팩터링` |
| 5 | `test` | `## ✅ 테스트` |
| 6 | `chore` | `## 🔧 기타 작업` |
| 7 | `perf` | `## ⚡ 성능 개선` |
| 8 | `ci` | `## 👷 CI/CD` |
| 9 | `other` | `## 📦 기타 변경` |
| (최하단 고정) | malformed | `## ⚠️ 분류 보류` |

이 순서는 커밋 개수·알파벳 등으로 재정렬하지 않고 항상 위 순서로 고정 출력한다 (plan 4.1절). `⚠️ 분류 보류`는 9개 정식 섹션 뒤, 문서 최하단에만 위치한다 (plan 5.3절).

## 4. 항목(bullet) 형식

모든 항목은 `-`로 시작하는 마크다운 리스트 항목 1줄이며, 항목 내부 줄바꿈은 없다 (원본 subject 그대로 한 줄).

| 케이스 | 형식 | 예시 |
|---|---|---|
| 정식 type, scope 있음 | `- **[{scope}]** {subject}` | `- **[bf-2186]** renderBadge + HTTP 핸들러 TDD 구현` |
| 정식 type, scope 없음 | `- {subject}` | `- 의존성 업데이트` |
| `other` 섹션, scope 없음 | `- **[{type}]** {subject}` | `- **[build]** 번들러 업그레이드` |
| `other` 섹션, scope 있음 | `- **[{type}/{scope}]** {subject}` | `- **[revert/bf-2150]** 배지 렌더링 되돌림` |
| `⚠️ 분류 보류` | `- {raw}` (태그 없음, 원문 그대로) | `- Merge branch 'main' into feature/x` |

섹션 내부 항목 순서는 입력 배열의 원래 순서를 보존하는 안정 정렬만 적용한다 (재정렬 없음, plan 4.3절).

## 5. 빈 입력 레이아웃 (plan 6.2절)

`commits`가 빈 배열이거나 모든 라인이 malformed라서 유효 섹션이 하나도 없는 경우, 본문을 **정확히 "변경 없음"** 한 줄로 대체한다. 제목(H1)은 정상 케이스와 동일하게 출력한다.

```
# 릴리즈 노트

변경 없음
```

## 6. 전체 레이아웃 골격

```
# {title}

## ✨ 새로운 기능
- 항목...

## 🐛 버그 수정
- 항목...

...(3~9번 섹션, 커밋 있는 섹션만)...

## ⚠️ 분류 보류
- raw...
```

## 7. dev 구현 가이드 (BF-2192 참고)

1. H1 제목 문자열 결정: `--title` 지정 시 `# {title}`, 미지정/빈 문자열이면 `# 릴리즈 노트` (plan 7장).
2. 4~5장 규칙대로 각 섹션의 헤더+항목 블록을 조립한 뒤, 커밋 0개인 섹션은 배열에서 제외.
3. malformed 라인이 있으면 `⚠️ 분류 보류` 블록을 마지막에 추가.
4. 섹션 블록들을 `\n\n`으로 join하여 본문 조립 (섹션 간 빈 줄 1개 규칙).
5. 유효 섹션이 하나도 없으면 본문을 `"변경 없음"` 문자열로 대체 (5장 규칙).
6. 최종 문자열 = `{H1 제목}\n\n{본문}`.
